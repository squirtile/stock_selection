# 页面展示优化建议

日期：2026-10-05

范围：当前工程页面展示部分，仅针对 `web/templates/index.html` 与 `static/workspace.css` 的展示体验做评估，不涉及策略、接口、数据处理等业务逻辑。

## 总体结论

当前页面已经具备较完整的研究工作台形态，包含策略扫描、盘中实时、策略复盘、资金动向、板块热度、连板天梯等模块。整体信息完整，但首屏信息密度偏高，导航与筛选层级较多，宽屏空间利用率和移动端适配仍有优化空间。

建议优先围绕「首屏层级」「导航结构」「颜色语义」「复盘摘要」「移动端表格」进行迭代。

## 一、优先优化项

### 1. 首屏信息密度偏高

当前顶部区域包含：

- 品牌标题
- 页面副标题
- 数据日期
- 股票总数
- 刷新按钮
- 更新说明
- 6 个主导航入口
- 策略筛选区域

用户进入页面后需要扫描较多信息，核心操作入口不够聚焦。

建议：

- 弱化“每日 18:30 盘后更新”等说明性信息。
- 将更新说明改为较轻量的辅助提示。
- 保留数据日期、刷新、核心导航作为首屏重点。
- 策略筛选区与页面标题之间增加更明确的视觉分隔。

### 2. 主导航项目较多

当前主导航包含：

- 策略扫描
- 盘中实时
- 策略复盘
- 资金动向
- 板块热度
- 连板天梯

桌面端尚可，但在窄屏或移动端上容易拥挤。

建议：

- 桌面端保持横向导航。
- 移动端改为横向滚动导航，避免挤压换行。
- 可考虑按使用频率分组，例如“选股”“复盘”“市场”。
- 当前激活状态可以更突出，减少用户迷失。

### 3. 页面宽度与内容布局不完全匹配

页面主体最大宽度较大，但部分模块仍以单列卡片或列表展示，宽屏下空间利用率不足。

建议：

- 策略列表在宽屏下使用双列布局。
- 板块热度、资金动向可使用卡片网格。
- 复盘摘要和表格分层展示。
- 窄屏保持单列，避免横向滚动过多。

### 4. 颜色语义需要进一步统一

页面中同时存在：

- 红涨绿跌
- 蓝色主强调
- 绿色成功状态
- 黄色提示状态

不同模块之间的颜色含义可能不够一致。

建议：

- 股票涨跌统一使用红涨绿跌。
- 主操作和当前选中统一使用蓝色。
- 成功、命中、有效等状态避免与“下跌绿色”混淆。
- 建立统一 CSS 变量，例如涨、跌、中性、强调、警告。

### 5. 策略复盘区域过长

策略复盘中包含历史胜率、盘中胜率、复盘快照和个股明细，纵向内容较多。

建议：

- 增加复盘摘要指标卡。
- 摘要指标可以包含整体胜率、平均收益、有效信号数、最近复盘日期。
- 历史胜率列表默认展示 Top N，其余折叠。
- 明细表格保留排序能力，但降低首屏占用。

## 二、交互体验优化

### 1. 当前筛选路径不够明确

主筛选和二级筛选视觉较接近，用户切换后不一定能快速确认当前视图。

建议：

- 增加当前筛选路径提示，例如：`策略扫描 / 缠论选股 / 买点`。
- 当前筛选结果数量展示得更明显。
- 二级筛选可以根据分组增加间距或标签标题。

### 2. 数据日期与刷新状态可以更明确

当前顶部展示数据日期，但对数据是否过期、是否为最新结果提示不足。

建议：

- 区分“数据日期”和“页面刷新时间”。
- 如果数据日期不是最近交易日，可显示轻量警示。
- 刷新按钮增加 hover 或点击后的加载反馈。

### 3. 空状态需要更具指导性

当前空状态多为“暂无数据”“加载中”“加载失败”。

建议：

- 增加原因说明，例如“盘前尚未生成”“接口暂不可用”“无符合条件股票”。
- 增加下一步建议，例如“盘后运行数据生成任务后刷新”。
- 不同模块使用统一的空状态组件样式。

### 4. 加载反馈需要统一

异步模块使用文字加载提示，但不同模块表现不一致。

建议：

- 统一加载状态样式。
- 可以使用轻量 skeleton 或 loading 卡片。
- 加载失败时提供重试入口。

### 5. 表格移动端体验需要重点检查

资金、复盘、连板等模块存在多列表格，小屏幕上可能出现横向溢出、字号过小或阅读困难。

建议：

- 移动端将复杂表格改为卡片化布局。
- 保留关键字段，次要字段折叠展示。
- 对必须保留的表格增加横向滚动容器。
- 重要列可以固定或前置展示。

## 三、视觉细节优化

### 1. 品牌图标风格

当前顶部使用 emoji 作为品牌标识，亲和力较强，但与“策略研究工作台”的专业风格略有差异。

建议：

- 可替换为更简洁的图标或字母标识。
- 保持标题视觉稳定，减少 emoji 在不同系统下的显示差异。

### 2. 阴影与层级

页面卡片、按钮、导航均有不同程度的边框和阴影，整体层级较多。

建议：

- 减少低优先级模块的阴影。
- 重要模块使用更明显的卡片层级。
- 次要信息使用浅背景或分割线即可。

### 3. 小字号内容较多

部分说明文字、元信息、辅助数据使用 `10px–12px` 字号。

建议：

- 移动端避免低于 `12px`。
- 关键数据不小于 `14px`。
- 辅助说明可通过颜色弱化，而不是单纯缩小字号。

### 4. 股票卡片点击反馈可增强

股票卡片已有 hover 效果，但可点击属性可以更明确。

建议：

- 增加“展开详情”或箭头提示。
- 点击后保持展开态样式。
- 移动端增加按压反馈。

### 5. 支持卡片位置可后移

如果支持二维码属于低频内容，放在核心选股流程附近可能会干扰主要任务。

建议：

- 放到页面底部。
- 或折叠为“支持项目”入口。
- 避免影响首屏核心操作。

## 四、代码维护层面的展示优化

### 1. 减少 JavaScript 拼接内联样式

当前部分动态模块通过 JavaScript 拼接 HTML 和内联样式，例如板块明细、资金列表、连板表格。

问题：

- 样式分散，后续维护成本高。
- 响应式适配不方便。
- 主题统一调整困难。

建议：

- 将可复用样式迁移到 `static/workspace.css`。
- JavaScript 只负责切换 class 和渲染数据。
- 为动态模块建立统一 class 命名。

### 2. 统一模块状态组件

加载、空数据、错误等状态目前散落在不同模块中。

建议：

- 抽象统一样式：loading、empty、error、warning。
- 文案保持一致结构：状态 + 原因 + 下一步。
- 减少重复 HTML 片段。

### 3. 响应式规则可以进一步集中

展示层已经有响应式基础，但复杂模块仍需逐个检查。

建议：

- 按断点集中维护布局规则。
- 优先覆盖导航、筛选器、卡片列表、表格。
- 保证移动端核心操作路径清晰。

## 五、建议迭代顺序

1. 优化首屏信息层级和主导航布局。
2. 统一涨跌、状态、命中率等颜色语义。
3. 给策略复盘增加摘要区，压缩长列表。
4. 优化移动端筛选器、表格和卡片布局。
5. 统一加载、空状态、错误状态。
6. 将动态模块中的内联样式逐步迁移到 CSS。
